用户只做三件事

授权一次，投料（图 + 价格），审红项。类目、属性、英文标题、图片银行、发布队列都不是用户的工作。

1. 投料

拖 1～6 张图。建议再写货号、FOB、MOQ。店铺默认只在第一次问。

2. 审稿

只展开红黄项。绿的折叠。价格和 MOQ 必须人看一眼。

3. 队列

点发布即可离开。失败按字段回草稿，改完重发。

用户

授权店铺

跳转官方 OAuth，不收集密码。

openapi-auth.alibaba.com → /auth/token/create

店铺

默认交易 / 物流（只填一次）

询盘或一口价、币种、港口、付款、交期、运费模板、包装。

product.group.get shippingline.template.list

用户

投料

每条商品真正要给的：图。建议给货号、价格、MOQ。

AI

看图 → 类目 → 属性 → 英文内容

先理解，再在类目树里检索叶子类目，再按 schema 对齐属性，最后写标题和详情。

叶子类目 → /alibaba/icbu/product/schema/get（顶层 cat_id）

系统

图片银行 + 质检

原图上传拿 url/fileId。标题长度、违禁、必填空在提交前拦掉。

/alibaba/icbu/photobank/upload

用户

审红黄项

类目不确定、属性对不上、价格/MOQ。绿项不用点开。

系统

排队发布

把填好的 XML 交给官方。限流、重试、记下 product_id。

/icbu/product/schema/add（publish_request）

第一期就做到发布询盘品

一口价 SKU、多店复制、在线改品放到第二期。先把「传图出价 → 自动成稿 → 审红项 → 发出去」跑通。
